# TRACEWISE — تريس وايز

> **افهم المشكلة. اعثر على السبب. تحقّق من الحل.**

مساعد المبرمج الذكي — تطبيق موبايل حقيقي (React Native / Expo) يحوّل كل مشكلة برمجية إلى **Debug Case** مستقلة تمر بمسار هندسي كامل:

```
المشكلة ← جمع الأدلة ← تحليل الأدلة ← الاحتمالات ← السبب الجذري ← خطة الإصلاح ← تطبيق الإصلاح ← التحقق ← حفظ المعرفة
```

## لماذا TRACEWISE ليس chatbot؟

- **لا قرار بدون دليل**: التحقق من الحل يتطلب دليلًا جديدًا يناقض إشارة الفشل (مثل `HTTP 401 → HTTP 200`)، وإلا تبقى الحالة «مرجح الحل» فقط.
- **القواعد المحلية أولًا**: محرك تشخيص محلي (15+ قاعدة) يعمل **بدون إنترنت** تمامًا. الذكاء الاصطناعي اختياري، ويُستدعى بعد القواعد المحلية وبعد حجب الأسرار، ولا يقرر التحقق أبدًا.
- **لا سر يُخزَّن**: حجب تلقائي (Redaction) للـ Tokens وJWT وكلمات المرور ومفاتيح API وبيانات قواعد البيانات قبل التخزين أو أي إرسال.
- **لا كتابة على GitHub بدون موافقتك**: التكامل قراءة فقط، وأي عملية كتابة تمر بدورة: **اقتراح ← موافقة ← تنفيذ**.

## حالات المشكلة

`مفتوحة ← قيد التحليل ← خطة إصلاح ← مرجح الحل ← تم التحقق ← مغلقة`

آلة حالات قانونية فقط — مع مسار انتكاسة (`مرجح الحل ← خطة إصلاح`) وإعادة فتح.

### ما الجديد (أدوات مطور موبايل v3)

| المسار | الآن |
| --- | --- |
| المشاريع | مساحات عمل كاملة (Flutter/Node/…) مع ربط الحالات والتصفية |
| الرحلة | خط زمني كامل + «ما الذي تغير؟» + مشاكل مشابهة عند الفتح |

| الذاكرة | تظهر تلقائيًا عند الإنشاء وفي تبويب الرحلة مع شارة موثوقية |
| التحليل | التغييرات الحديثة ترفع ثقة الفرضيات المرتبطة |

## بناء Release APK — سحابيًا بالكامل (GitHub Actions)

لا يتطلب البناء أي أدوات محلية (لا npm/Gradle/Android Studio/Metro على جهازك).

- **المسار**: push إلى `arena/01a09d49-tracewise` ← workflow «Android APK» على `ubuntu-latest`:
  Node 22 → JDK 17 → `npm ci` → `expo prebuild` → `./gradlew assembleRelease` (مقيد بـ20 دقيقة) ← تحقق ← Artifact.
- **Artifact**: `tracewise-standalone-apk` ويحوي `app-release.apk` — إصدار release مستقل:
  حزمة JavaScript مضمّنة داخل APK (`assets/index.android.bundle`)، لا يحتاج Metro، قابل للتثبيت المباشر على Android.
- **التحقق المضمّن في البناء**: وجود الملف وحجمه + وجود الـbundle داخله + فحص `apksigner` عند توفره.
- **التوقيع**: مفتاح debug المولّد تلقائيًا في CI (سلوك Expo الافتراضي لـassembleRelease) — صالح للتثبيت الاختباري؛
  للتوزيع الرسمي يلزم keystore خاص (خطوة لاحقة اختيارية).
- **التنزيل**: من صفحة الـRun ← Artifacts ← `tracewise-standalone-apk`.

> ملاحظة: EAS Build غير مستخدم لأنه يتطلب `EXPO_TOKEN` (سر) — والسياسة المعتمدة: صفر أسرار في المستودع/CI.

## البنية (Clean Architecture)

```
src/
├── domain/        # الأنواع، آلة الحالات، الخطورة، البصمة (نقية 100%)
├── diagnosis/     # قاعدة القواعد المحلية + محرك التشخيص
├── verification/  # محرك التحقق (الدليل يقرر، لا AI)
├── security/      # Redaction + Scanner (استخراج الإشارات)
├── ai/            # بوابة AI اختيارية (متوافقة مع OpenAI)
├── integrations/  # GitHub Client (READ ONLY + اقتراح/موافقة/تنفيذ)
├── storage/       # AsyncStorage + SecureStore + حالات تجريبية
├── state/         # AppStore (Context + أفعال دورة الحياة)
├── core/          # i18n (ar/en) + Theme (RTL حقيقي)
├── ui/            # نظام التصميم (بطاقات، أزرار، شارات…)
└── features/      # الشاشات
```

## بناء APK (Android)

المتطلبات: JDK 17 + Android SDK (أو استخدم CI).

```bash
npm run apk          # ينتج android/app/build/outputs/apk/debug/app-debug.apk (قابل للتثبيت)
npm run apk:release  # نسخة release (تتطلب keystore)
```

تتحقق أوامر البناء الآن من Java 17+ قبل البدء، وتستخدم `gradlew.bat` تلقائيًا على Windows و`./gradlew` على macOS/Linux. إذا ظهر خطأ Java 11، اضبط `JAVA_HOME` إلى تثبيت JDK 17 أو أحدث ثم أعد الأمر. لا يُعد البناء ناجحًا إلا بعد ظهور رسالة الإكمال ووجود ملف APK في المسار المطبوع.

**أو عبر GitHub Actions (بدون أدوات محلية):**
انسخ `ci/android-apk.yml` إلى `.github/workflows/android-apk.yml` في المستودع،
وسيُبني APK تلقائيًا عند كل push ويمكنك تنزيله من تبويب Actions → Artifacts.

إعدادات Android المضبوطة: اسم TRACEWISE، حزمة `com.tracewise.app`،
`supportsRtl=true` (RTL من أول إقلاع عبر `I18nManager.forceRTL`)، وضع Portrait،
أذونات دقيقة (INTERNET + READ_MEDIA_IMAGES + VIBRATE)، أيقونة Adaptive، Splash كحلي.

```bash

```

تغطي الاختبارات: **Redaction (مع Idempotency)، Diagnosis، Severity، Case State Machine،

مع إثبات صفر اتصال شبكة (Offline كامل).

## مبادئ الأمان

1. حجب الأسرار دائمًا مفعّل — لا يمكن إيقافه (Idempotent: لا يعيد حجب المحجوب).
2. الأسرار تُحفظ فقط في SecureStore (مفاتيح GitHub/AI) ولا تظهر في السجلات.
3. مركز الأمان يعرض كل اتصال خارجي محتمل.
4. إرسال البيانات للذكاء الاصطناعي يتطلب تفعيلًا + موافقة صريحة (نافذة تأكيد) + حجبًا مسبقًا + **حارس ثانٍ يرفض الطلب إذا بقي أي سر بعد الحجب**.
5. AI يقترح فقط — لا يغيّر حالة التحقق أبدًا، وثقته مسقوفة بـ 0.75.
6. معالجة Rate Limit (429 + Retry-After) وTimeout واختبار اتصال من الإعدادات.
7. اختبار آلي يضمن خلو البيانات التجريبية من أي أسرار.
